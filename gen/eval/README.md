# 평가 세트

프롬프트를 고쳤을 때 **정말 좋아졌는지**를 느낌이 아니라 숫자로 확인하기 위한 고정 시험지다.
같은 지문 10편([passages.txt](passages.txt))으로 버전마다 문항을 만들고, 같은 기준으로 채점해 비교한다.

## 순서

```bash
cd gen
./.venv/bin/python scripts/run_eval.py generate v2-base        # 1. 생성 (지금 기본 프롬프트)
#    → eval/runs/v2-base/ 에 auto.md(자동 지표)와 sheet.csv(채점표)가 생긴다
#    2. sheet.csv 를 엑셀·넘버스·구글시트로 열어 아래 기준대로 채점하고 CSV로 저장
./.venv/bin/python scripts/run_eval.py score v2-base           # 3. 집계

# 프롬프트를 고친 뒤
./.venv/bin/python scripts/run_eval.py generate v3-try --prompt quiz_v3
./.venv/bin/python scripts/run_eval.py score v2-base v3-try    # 나란히 비교
```

생성이 중간에 끊기면 같은 명령을 다시 실행하면 된다. 이미 만든 지문은 건너뛴다.
`eval/runs/`는 커밋한다. 나중에 "v2 때는 몇 점이었지?"를 다시 볼 수 있어야 해서다.

## 자동 지표 (auto.md)

사람 없이 바로 나온다. 내용이 맞는지는 모르지만 **쏠림**은 잡는다.

| 지표 | 무엇을 보나 | 바라는 모습 |
| --- | --- | --- |
| 스킬 분포 | 네 가지 스킬이 고루 나오나 | 지금은 vocab이 거의 안 나옴 |
| 난이도 분포·표준편차 | 지문마다 난이도를 다르게 매기나 | 표준편차 0이면 구분을 못 하는 것 |
| 정답이 가장 긴 선택지인 비율 | 길이만 보고 찍어도 맞나 | 25% 근처 (무작위 수준) |
| 오답 유형 분포 | 한 유형에 몰리나 | missed_detail 쏠림이 줄어야 함 |
| 오답 유형이 겹치는 문항 | 한 문항의 오답 3개가 같은 오류를 노리나 | 0 |

## 사람 채점 (sheet.csv)

한 줄이 문항 하나다 (10편 × 3문항 = 30줄). 각 항목에 **1(통과) 또는 0(실패)**을 적는다.
애매하면 0을 주고 `메모`에 이유를 적는다. 빈 칸은 집계에서 빠진다.

| 열 | 1을 주는 경우 | 0을 주는 예 |
| --- | --- | --- |
| `정답_유일` | 지문을 근거로 정답이 하나로 정해진다 | 오답 중 하나도 지문상 맞는 말이다 / 정답이 지문과 어긋난다 |
| `지문_필요` | 지문을 안 읽으면 풀 수 없다 | 상식으로 바로 답이 나온다 ("정부가 안전을 강화한다" 류) |
| `근거_적절` | 근거 문장이 정답을 직접 뒷받침한다 | 근거가 다른 내용을 말하거나, 정답과 관련이 약하다 |
| `오답_매력` | 오답 3개 모두 대충 읽으면 고를 만하다 | 문법이 어색하거나, 지문과 전혀 무관한 오답이 있다 |
| `해설_정확` | 해설·오답 설명에 틀린 내용이 없다 | 숫자를 잘못 옮김 / 정답 번호를 잘못 말함 / 지문에 없는 말 |
| `스킬_일치` | 라벨이 실제로 재는 능력과 맞다 | `inference`라는데 지문에 그대로 적힌 걸 찾는 문제다 |

추가로 두 칸이 더 있다.

- `오답유형_맞은수` (0~3): `distractors` 열의 오답 3개 중, 붙은 오류 유형 라벨이 그 오답의
  설계와 맞는 개수. 라벨은 "학습자가 실제로 그렇게 틀렸다"가 아니라 **출제 의도**라는 점에 주의
  (`neuroknot_gen/skills.py` 참고).
- `사람_난이도` (1~5): 지문마다 **첫 문항 줄(q=1)에만** 적는다. 지문을 읽고 느낀 난이도.
  모델이 매긴 `difficulty_hint`와 얼마나 같이 움직이는지(상관계수)를 본다.

### 결과 읽는 법

- **전 항목 통과율**: 여섯 항목을 모두 통과한 문항의 비율 = 손보지 않고 앱에 내보낼 수 있는 문항.
  가장 중요한 숫자다.
- **스킬별 통과율**: 어느 스킬 문항이 약한지. 프롬프트에서 어디를 고칠지 정할 때 쓴다.
- **난이도 일치**: 1에 가까울수록 모델 난이도가 사람 감각과 맞는다. 모델이 전부 같은 값을 주면
  계산할 수 없어 `-`로 나온다 (= 난이도 구분 실패).

### 채점할 때 지킬 것

- 한 실행의 30문항은 **한 번에 같은 사람이** 채점한다. 사람마다 기준이 조금씩 달라서다.
- 두 버전을 비교할 때는 가능하면 어느 쪽이 새 버전인지 모르게 채점한다.
- 채점 기준을 바꾸면 이전 실행도 다시 채점해야 비교가 된다.

사람 채점은 선택이다. 자동 지표만으로도 지금 알려진 쏠림(난이도·스킬·오답 유형)은 보인다.
내용 품질까지 비교하고 싶을 때 채점한다.

## 지문 구성

`fixtures/`의 10편을 그대로 쓴다. 분야가 한쪽에 몰리지 않도록 앱의 관심 분야 중 7개 이상이
들어가게 골랐다. 출처·이용 조건은 [fixtures/README.md](../fixtures/README.md).

평가 세트는 **시험지**라서 함부로 바꾸지 않는다. 지문을 바꾸면 이전 실행과 점수를 비교할 수 없다.
지문을 늘리거나 바꿔야 하면 새 세트로 만들고 이전 결과와 섞지 않는다.
