# 샘플 지문 (fixtures)

문항·해설 생성을 개발하는 동안 쓰는 고정 지문입니다.
슬라이스 1의 지문 수집 파이프라인이 완성되면 DB에서 같은 형식으로 읽어오므로,
여기 JSON 구조는 `passages` 테이블 컬럼과 같게 유지합니다.

## 출처와 이용 조건

모든 지문은 [대한민국 정책브리핑](https://www.korea.kr)의 정책뉴스 본문이며,
**공공누리 제1유형(출처표시)** 표시가 붙은 글만 골랐습니다.
제1유형은 출처를 표시하면 상업적 이용과 변형이 가능합니다.

수집할 때 지킨 것:

- **텍스트만** 사용합니다. 정책브리핑의 사진·이미지·동영상은 공공누리 대상이 아니며
  저작권자가 따로 있어 쓸 수 없습니다.
- 언론사가 재가공한 기사가 아니라 **정책브리핑 원문**만 사용합니다.
- 각 문서의 공공누리 유형을 개별 확인합니다. 제2·3·4유형은 상업적 이용이나 변형이
  제한되므로 제외합니다. (실제로 후보 중 제4유형 문서가 있어 제외했습니다.)

## 형식

```json
{
  "id": "fx-001",
  "title": "문서 제목",
  "category": "comp_tech",
  "source": "대한민국 정책브리핑 (과학기술정보통신부)",
  "source_url": "https://www.korea.kr/news/policyNewsView.do?newsId=...",
  "license": "KOGL-1",
  "body": "첫 문단...\n\n둘째 문단..."
}
```

`body`의 문단 구분은 빈 줄(`\n\n`)입니다. 앱의 읽기 화면이 같은 기준으로 문단을
나누고, 해설의 근거 문장 검증도 이 원문과 글자 그대로 대조하므로
**본문은 손대지 않습니다.** (원문의 오탈자도 그대로 둡니다.)

## 지문을 더 추가할 때

1. [정책브리핑 정책뉴스](https://www.korea.kr/news/policyNewsList.do)에서 글을 고릅니다.
2. 글 하단에 **공공누리 제1유형** 표시가 있는지 확인합니다.
3. 아래 기준을 만족하는지 봅니다. 문항 3개를 뽑아야 하므로 중요합니다.
   - 600~2,000자, 문단 3개 이상
   - 본문에 구체적인 수치나 고유명사가 있음 (`fact` 문항)
   - 원인·결과나 대조 구조가 있음 (`inference` 문항)
   - 전문 용어가 본문 안에서 설명됨 (`vocab` 문항)
   - 글 전체를 관통하는 주장이 있음 (`main_idea` 문항)
4. 행사 공지, 인사 발령, 표·그래프가 있어야 이해되는 글은 제외합니다.
