## Generation 데이터 출처

등록된 로컬 worktree들의 `gen/out/`에서 리뷰에 언급된 `fx-001~005.json` 생성 출력을 찾지 못했다.
따라서 실제 5편이 모두 힌트 2라는 관측은 리뷰의 보고이며 이번 실행에서 직접 검증한 결과는 아니다.
원격 `feat/gen-api`의 `185c8a4`를 읽기 전용으로 확인했다. 해당 브랜치의 `gen/fixtures/fx-001~005.json`은
입력 원문 지문이다. 이를 생성된 퀴즈로 사용하지 않았다. Generation 스키마·검증기와 현재 워크플로 기준의
해당 파일들 사이에는 차이가 없었다.

진단 기본 입력은 `ml/fixtures/service_workflow.json`의 **합성 퀴즈 2편·6문항**이다.
`GeneratedQuiz` 스키마와 `check_quiz()`를 사용해 실제 본문의 근거·오답 인덱스 등과 문항별 유효 스킬을 검증한다.
Prediction의 세 문항·서로 다른 세 스킬 조건도 적용한다. 외부 입력에 검증 오류가 있으면 중단한다.
입력 파일·Generation 코드·원래 모델 정책을 수정하지 않는다.

Generation 출력에는 `passage_id`, `prompt_version`, `model`, `quiz`가 있으며,
`quiz`에는 1~5의 `difficulty_hint`와 세 문항이 있다. 출판 버전은 서비스 호출자가 별도로 부여한다.
현재 `PredictionService`는 `passage_id`, `quiz_version`, 슬롯을 해시한 기존 ID를 유지한다.
진단에서는 `diagnostic-v1`이라는 합성 출판 버전을 사용한다. 실제 서비스의 버전 발급 계약은 별도 합의 대상이다.

`feat/gen-api`의 앱용 `QuizView`는 정답이 제외된 응답이다. 내부 채점 키가 포함된 `GeneratedQuiz`와
검수 본문을 Prediction 등록 경계에 전달해야 한다. 해당 브랜치의 `AttemptRecord`는
`passage_id`·`question_index`·`prompt_version`을 사용하며 불변 출판 버전과 안정적인 문항 ID가 없다.
이 기록을 현재 서비스에 바로 연결하려면 ID·버전·노출·제출 계약을 먼저 합의해야 한다.

## 재현 방법

`ml/`의 기존 의존성을 설치한 Python 환경에서 실행한다.

```bash
python scripts/diagnose_difficulty.py
python scripts/diagnose_difficulty.py --generated-dir ../gen/out --passages-dir ../gen/fixtures
```

외부 입력 모드는 실제 생성 출력 파일과 원문 지문 파일을 각각 읽는다. 두 디렉터리에 있는 JSON을
저장된 지문 ID로 연결하며, 진단 대상은 지문당 출판본 하나다. 출력 출처 표시는
`synthetic_test_fixtures` 또는 `supplied_generation_outputs`이며, 후자는 생성 과정의 진위를 보증하지 않는다.
`--item-stars 1 3 5`는 슬롯 순서대로 적용하는 **가정한 별점**이다.
기본 `--near-tolerance 0.01`은 점수 차이가 0.01 이하인 후보 쌍의 수와 비율을 계산한다.
후보가 하나일 때 쌍의 수는 0, 비율은 `null`이다. 등록·추천만 수행하며 노출·풀이·Elo 갱신은 수행하지 않는다.
출력에는 채점 키·본문·선택값을 포함하지 않는다.

## 합성 입력에서 관측한 결과

원래 힌트는 1이 1편(50%), 2가 1편(50%), 3~5가 각각 0편이었다.
아래 확률은 각 온보딩 레벨의 초기 6문항 확률 최솟값과 최댓값이다. 사용자에게는 풀이 이력이 없다.

| 온보딩 | 원래 힌트의 확률 범위 | 전부 힌트 2인 가정의 확률 | 원래 힌트 선택 | 별점 1·3·5 가정의 선택 |
| --- | --- | --- | --- | --- |
| warming_up | 0.450166~0.645656 | 0.450166 | demo-library | demo-library |
| cruising | 0.622459~0.785835 | 0.622459 | demo-library | demo-garden |
| high_speed | 0.750260~0.869892 | 0.750260 | demo-garden | demo-garden |
| autonomous | 0.858149~0.930862 | 0.858149 | demo-garden | demo-library |

각 레벨에서 원래 후보의 한 쌍은 동점도 근접 점수도 아니었다. 모든 힌트를 2로 바꾼 반사실 조건에서는
두 후보가 동점이 됐다. 두 지문 모두 슬롯별 별점을 1·3·5로 지정해도 같은 확률 조합을 갖게 되어 동점이 됐다.
이 별점 가정은 네 레벨 중 두 레벨의 선택을 바꿨다. 별점을 추가했다는 사실만으로 후보 간 구분이 개선되지는 않는다.

`select_passage()`의 비교 순서는 총점 내림차순, 목표 거리 오름차순,
`SHA256(user_id + NUL + passage_id)`, 지문 ID다. 첫 두 값이 정확히 같을 때 해시가 선택을 결정한다.
근접 점수 임계값은 진단용이며 실제 추천의 동점 허용 오차로 사용하지 않는다.
동일 힌트는 미학습 사용자의 같은 prior에서 문항 확률을 같게 만든다. 학습된 스킬별 θ, 문항별 b,
커버리지·취약 스킬 가산점이 다르면 동일 힌트가 같은 추천 점수를 뜻하지 않을 수 있다.

## 회귀 검증과 한계

기존 테스트는 동일 버전 재등록, 다른 내용의 같은 버전 충돌, 새 버전 노출과 이전 채점 키 유지,
같은 ID의 다른 버전 거부를 다뤘다. 부족한 검증을 보강했다.

- 버전 간 세 문항 ID의 완전 분리와 복원 전후 이전 노출 채점.
- 학습된 문항 재등록과 거부된 재등록이 전체 체크포인트·난이도·갱신 횟수를 보존하는지 확인.
- 동일 ID에 다른 스킬 또는 버전을 연결하면 복원 전후에 원자적으로 거부하는지 확인.
- 진단의 입력 검증, 입력 순서에 따른 재현성, 근접 점수와 해시 동점의 구분, 외부 출력 모드 검증.

실제 정답률·난이도 정답·보정도·학습 효과는 이 초기값 진단으로 판단할 수 없다.
문항별 별점과 힌트는 임시 신호다. 실제 생성 출력 확보, 실제 응답과 표본량 확인 후 별도의 품질 평가가 필요하다.
ID 형식, Generation의 문항별 별점 제공, 실제 노출 주체, DB 동시 갱신과 해설 공개 정책은 팀 합의 후 진행한다.

Windows / Python 3.12.10에서 기존 환경의 의존성을 재사용해 전체 테스트 **189개가 통과**했다.
기준선 178개를 유지하면서 11개 사례를 보강했다. 초기 격리 실행에서 임시 디렉터리 권한 오류가 있어
같은 Python 환경에서 권한을 확보한 실행으로 전체 검증을 마쳤다.
기준 커밋의 소스를 별도 임시 디렉터리에 추출해 아래 세 명령의 기본 시드 출력을 비교했다.
지문 실험과 워크플로 출력은 같았고, Elo 실험은 그래프 저장 디렉터리 문자열을 제외한 전체 출력이 같았다.
생성된 그래프는 `ml/results/`의 기존 제외 규칙을 따른다.

```bash
python -m pytest
python scripts/run_experiment.py
python scripts/run_passage_experiment.py
python scripts/run_service_workflow.py
```
