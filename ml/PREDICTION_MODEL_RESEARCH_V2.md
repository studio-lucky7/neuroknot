# Prediction Model Research V2 — 1단계

이 연구는 V2 모델의 우월성을 주장하지 않는다. 기존 Elo 수식·정책의 운영 기본값·PredictionService 공개 계약은 그대로 두고, 평가 방법과 정책 구성요소, 설정 민감도를 연구했다. 모든 추가 코드는 `ml/` 안에 있다.

기준 커밋은 `origin/fix/pred-review-hardening`의 `d17ac32`, 연구 브랜치는 `research/pred-model-evaluation-v2`다. 아래 숫자는 저장된 합성 실험 결과이며 실제 사용자 성능이 아니다. 표의 ±는 **시드 간 표본 SD**, 대괄호는 **시드 단위 Student-t 95% 신뢰구간**이다. 같은 응답을 독립 표본처럼 세어 CI를 축소하지 않았다.

## 3. 평가 설계와 누출 방지

출처: [사전 계획](research_v2/PLAN.md), [설정·환경 manifest](research_v2/artifacts/tune_manifest.json), [연구 코드](research_v2/experiment.py), [검증 manifest](research_v2/artifacts/validate_manifest.json). 재현: `python -m research_v2.run --phase tune`, 이후 `--phase validate`.

- 시드당 사용자 60명, 훈련 지문 60개/문항 180개, 16라운드/사용자 48응답. 기존 전체 크기 재현과 별도로 탐색 계산량을 제한했다.
- 탐색 시드 11/29/47, 검증 시드 101/211/307/401/503. 사용자·은행·풀이 시각·각 시각의 세 응답 uniform을 정책 간 공유한다. 문항별 잠재 응답이 동일하다는 뜻은 아니다.
- 주 분석 학습률은 0: 모든 정책에서 같은 실제 θ로 공통 평가가 가능하다. 0.01은 별도 강건성 분석으로만 사용한다.
- 독립 RNG의 공통 미학습 문항 40개(각 스킬 10개)를 등록하되 후보군에는 넣지 않는다. 사용자 0/6/48응답 시점에 상태를 읽고 평가할 뿐 업데이트하지 않는다. 같은 시드/사용자/시점/문항은 같은 평가 uniform을 사용한다.
- 같은 사용자 이력 길이의 실제 시각에 평가한다. 마지막 공통 평가는 각 사용자의 마지막 응답 직후이지 전체 사용자 학습 종료 후의 일괄 평가가 아니다. 전체 이벤트 순서/시각은 정책 간 같다.
- 훈련 갱신에는 선택된 현재 문항의 정오답만 전달한다. 등록에는 ID/스킬/별점/온보딩만 전달한다. 잠재 θ/b, 미학습 평가 응답, 미사용 source 응답은 모델/정책에 전달하지 않는다.
- 공통 Brier/AUC/log loss/ECE는 같은 평가 문항과 라벨을 사용한다. 추가로 `probability_mse=mean((p−p_true)^2)`와 `expected_brier=probability_mse+mean(p_true(1−p_true))`를 evaluator에서만 계산한다. 확률 MSE는 기대 Brier의 oracle 대비 초과분이다.
- 미학습 문항 b는 prior로 고정된다. 따라서 공통 평가는 **미학습 문항 일반화**이고, 학습된 문항 b의 개선을 직접 평가하지 않는다. 별도로 훈련 문항 전체/노출 문항/미학습 문항의 b RMSE를 저장한다.
- θ RMSE는 사용자×스킬, 사용자 스킬평균, 스킬별로 저장한다. raw logit 오차이며 gauge 정렬을 하지 않는다. 확률 MSE를 함께 봐야 한다.
- 정책 품질은 예측/실제 확률과 고정 .7 사이 평균 절대 거리, 실제 정답률, 첫 6개 정답률, cold 실제 확률과 .8 거리, 적용 설정 목표 거리, 사용자별 커버리지 격차 `(max count−min count)/total`로 평가한다. 목표 후보를 자기 목표만으로 유리하게 평가하지 않는다.
- 초기 관측 구간은 n_prior<6, 후기 구간은 n_prior≥30이다. 최대 48응답은 수렴이나 장기 학습 완료를 보장하지 않는다.

## 8. 결과 해석, 기대와 달랐던 실험

아래 독립 검증 수치는 `validate_seeds.csv`/`validate_paired.csv`에서 가져왔다 (`python -m research_v2.run --phase validate`). 탐색 결과를 인용한 부분은 `tune_seeds.csv`와 `--phase tune`, 동일 로그는 `replay_paired.csv`와 `python -m research_v2.replay`, 학습률 .01은 `learning_paired.csv`와 `--phase learning`이 출처다.

**예측 모델과 추천 정책의 구분.** 관측 AUC는 Random .76391, V1 .69850이지만 공통 AUC는 각각 .77264/.77259다. 공통 Brier의 Random−V1 차이는 −.00043, 95% CI [−.00350, .00264]다. 이 연구 범위에서 V1 예측기가 Random보다 열등하다는 결론은 지지되지 않으며, 동등성을 입증한 것도 아니다. 공통 평가를 추가한 이유가 실제로 드러난다. 실제 확률의 .7 목표 거리는 V1 .20650, Random .28257로 V1 쪽이 작다. 이는 추천 목적의 차이이며 예측 정확도나 학습량 증가와 다르다.

**커버리지 우위는 조건 의존적이었다.** 작은 연구 규모/반복 시드에서는 V1 격차 .07667, Random .07382로 Random이 평균상 더 균형적이다. Random−V1 차이 CI [−.01565, .00995]는 불확실하다. 기본 규모·시드 42의 V1 우위를 모든 조건으로 일반화할 수 없다. 주 연구는 사용자/은행 크기도 바뀌었으므로 원인이 시드인지 규모인지는 이 실험만으로 분해하지 못한다.

**가산점은 모든 지표를 개선하지 않았다.** 취약 가산점 제거의 공통 Brier 차이는 +.00088 [−.00266, .00441], 커버리지 차이는 +.00424 [−.00353, .01200]다. 평균 방향만으로 취약 보너스의 실효성을 확정할 수 없다. 커버리지 제거 역시 격차가 평균 +.01271 증가했지만 CI [−.00257, .02799]는 0을 포함한다. 둘 다 제거하면 실제 목표 거리는 −.00294 [−.00581, −.00006]로 작아졌고 커버리지 격차는 +.01583 [.00042, .03125]로 커졌다. 즉 보너스는 목표 적합도와 균형 사이 타협이다. 공통 예측 성능 개선은 확인되지 않았다. 다중 비교·적은 시드의 한계를 함께 적용해야 한다.

**cold 전환은 초기 정답률에 가장 분명한 차이를 냈다.** `no_cold`−V1의 첫 6개 정답률 차이는 −.05944 [−.09167, −.02722]다. 이는 쉬운 문항 배정의 결과일 수 있고, 스킬 획득·유지·이탈률 개선의 증거가 아니다. `target_only`의 커버리지 격차 증가는 +.02069 [.00920, .03218]로 나타났다. 초기 정답률은 사용자 자신의 초기 설정뿐 아니라 먼저 학습한 다른 사용자의 공유 b 갱신에도 영향받는다.

**탐색에서 기대했던 커버리지 .075의 예측 개선은 독립 검증에서 뚜렷하지 않았다.** 공통 확률 MSE 차이는 −.00016 [−.00090, .00058], θ RMSE 차이는 +.00095 [−.01067, .01256]다. 커버리지 격차는 평균 +.00521 증가했다. 운영 변경 후보로 밀어붙일 근거가 없다. 커버리지 .30도 주 검증에서는 격차 감소 −.00951 [−.02119, .00216]이 불확실했고, 공통 예측 개선은 없었다. 학습률 .01 조건에서는 격차 감소 −.00764 [−.01259, −.00269]가 관측됐지만 학습 효과 향상으로 해석하지 않는다.

**prior와 K는 서로 다른 경로로 민감했다.** 탐색의 별점 prior 제거는 공통 확률 MSE를 V1 .01241에서 .04907로 크게 높였다. 미학습 문항의 b를 prior만으로 예측하므로 이 결과에는 설계상 강한 영향이 있다. 실제 b를 구간화한 합성 별점이 현실의 지문 힌트보다 정확하다는 가정도 있다. 온보딩 prior 1.5배와 사용자 K 1.5배의 MSE는 각각 .01523/.01608로 V1보다 높았다. 강한 prior/빠른 갱신이 항상 좋다는 기대는 지지되지 않았다. 사용자 K를 더 빠르게 감소시키는 후보는 아래에서 별도로 해석한다.

`cold_target_070`과 `no_cold`는 이번 탐색에서 같은 궤적/수치를 보였다. 현재 지문 구조와 최소 스킬 횟수에서는 취약 보너스가 초기 단계에서 활성화될 근거가 없기 때문이다. 이를 두 번의 독립 증거로 세면 안 된다.

## 9. 개선 가치가 높은 후보와 다음 단계

### 우선순위 후보 — 운영 채택 결론 아님

1. **사용자 K의 감소율 .1→.2:** 동일 V1 로그 재학습에서 공통 Brier Δ −.00098 [−.00165, −.00030], 확률 MSE Δ −.00068 [−.00087, −.00050], θ RMSE Δ −.01529 [−.01910, −.01147]였다 (`replay_paired.csv`, `python -m research_v2.replay`). 그러나 추천까지 함께 바꾼 독립 검증에서는 Brier Δ −.00169 [−.00585, .00248], MSE Δ −.00080 [−.00269, .00108]로 불확실했다 (`validate_paired.csv`, `--phase validate`). **추정기 측 개선 가능성**이 가장 뚜렷하지만 고정 로그 결과를 폐루프 운영 효과로 옮겨 해석하면 안 된다. 더 긴 이력·실력 변화·망각 조건에서 재검증할 가치가 있다.
2. **커버리지 .30의 정책 목적 검증:** 주 검증에서 예측 개선 없이 평균 균형 개선 방향이 나타났고, .01 조건에서는 격차 감소 CI가 0을 제외했다. 위 8절의 paired 수치가 근거다. 목적을 예측 성능이 아닌 최소 스킬 노출 보장으로 명시하고, 약한 스킬 우대와 균형의 제품상 우선순위를 정한 뒤 검증해야 한다. 취약 가산점의 효용을 확인하지 못했으므로 단순화 대조군도 유지한다.
3. **문항 K/난이도 prior의 신뢰도 처리:** 탐색에서 문항 K 전체 크기 .5배의 훈련 b RMSE는 .25257, V1은 .33221이었다 (`tune_seeds.csv`, `--phase tune`). 공통 확률 MSE는 .01204/.01241이지만 고정 후보 선발 규칙에서 선택되지 않아 **독립 검증하지 않은 탐색 신호**다. 정확한 합성 별점을 과도한 갱신으로 훼손하는 상황일 수 있다. noisy/missing/지문 공통 힌트 조건을 추가하고, 새로운 검증 시드를 예약한 뒤 이 후보를 재검토한다.

### 다음 단계의 실제 모델 개선 연구

- 사용자·스킬별 표본이 적을 때 전체 사용자 실력과 스킬 추정치를 공유하는 계층적 shrinkage/불확실성 모델을 후보로 삼는다. 현재 K 민감도와 θ 오차가 동기이며, 이 단계에서 구현하거나 개선됐다고 주장하지 않는다.
- 난이도 초기값의 출처(문항별 별점/지문 힌트/중립)와 신뢰도를 구분하는 prior 모델을 설계한다. 실제 응답으로 b prior를 보정하고, 시간 순서 holdout 및 평가 문항 분리로 검증한다. 합성 실제 b에 맞춘 prior 튜닝은 실서비스 증거가 아니다.
- 실제 운영 데이터가 확보되면 동의된 공통 평가/소규모 무작위 감사 문항, 노출 로그, 장기 유지·전이 및 이탈 지표를 수집한다. 관측 확률 보정 모델은 별도 학습/검증 split에서 평가한다. 결정론적 선택 정책의 관측 로그만으로는 충분한 overlap이 없어 IPS 같은 보정을 적용하는 것만으로 선택 편향을 해결할 수 없다.

### 남은 한계

생성기와 모델이 같은 1PL 계열이며 문항 변별도, 추측, 지문 내 응답 상관, 피로·망각·중단, 실제 스킬 전이와 정책별 학습 효과가 없다. 동일 uniform은 분산을 낮추는 통제이지 노출 문항 차이를 제거하지 않는다. 미학습 문항 평가와 학습 문항 b 복원은 서로 다른 문제다. 실제 b에서 만든 별점, 단순 온보딩 노이즈, 모든 사용자 고정 길이, 제한된 은행/시드 때문에 외적 타당성이 낮다. 시드 CI는 이 생성기 내 변동만 표현하고 실제 사용자 모집단의 불확실성을 담지 않는다. 다중 비교 보정이나 동등성 검정은 하지 않았다. 초기/후기 및 민감도는 설명적 결과이며, 장기 정책 효과나 배포 우월성의 근거로 사용하지 않는다.

## 10. 재현 절차와 산출물

아래 명령은 저장소 루트에서 시작한다. Python 환경은 [requirements-lock.txt](research_v2/requirements-lock.txt)에 고정했다. 플랫폼 차이로 마지막 부동소수 자리는 달라질 수 있다. 실험은 외부 API/실사용자 데이터를 사용하지 않는다.

```powershell
cd ml
python -m venv .venv
.venv/Scripts/Activate.ps1

$env:PYTHONIOENCODING='utf-8'

python -m pytest -q --ignore=tests/test_research_v2.py --basetemp=research_v2/tmp-baseline
python -m research_v2.run --phase tune
# frozen_candidates.json 생성 완료 후만 검증 실행
python -m research_v2.run --phase validate
python -m research_v2.run --phase learning
python -m research_v2.replay
python -m research_v2.check_artifacts
python -m research_v2.report
python -m pytest -q --basetemp=research_v2/tmp-final
python -m pytest -c ../gen/pytest.ini ../gen/tests --basetemp=research_v2/tmp-gen -q
python scripts/run_learning_analytics.py
python scripts/run_service_workflow.py
python scripts/diagnose_difficulty.py
```

- `*_seeds.csv`: 모든 시드·설정별 집계값. 표에 생략한 적용 목표 거리, cold 실제 거리, 기대 Brier, b 노출 문항 오차 등도 포함한다.
- `*_summary.csv`: 모든 지표의 평균·표본분산·SD·95% CI. `*_paired.csv`: 같은 시드 V1 대비 차이와 CI. 시드가 유일한 통계 반복 단위다.
- `*_users.csv`: 사용자별 정답률, 커버리지, 목표 거리, 공통 예측 성능, θ RMSE.
- `*_theta.csv`: 사용자·스킬·시점별 추정/실제 θ와 오차. `*_items.csv`: 문항별 추정/실제 b, split/노출 여부.
- `*_manifest.json`: 정확한 설정, 시드, Python/라이브러리 버전, 실행 시 연구 코드 SHA-256. 튜닝 이후 추가된 replay/report 파일은 튜닝 manifest의 소스 목록에 없으며 튜닝 수치에는 관여하지 않는다.
- seed/설정/응답 생성 규칙으로 원시 온라인 로그를 다시 생성할 수 있다. `run(..., return_logs=True)`의 다섯 번째/여섯 번째 반환값이 관측/공통 로그다. 기존 `ml/results/`와 기존 기준 문서는 덮어쓰지 않았다(분리된 worktree의 기존 스크립트 기본 출력만 생성).
